📋 Executive summary

This is a Kubernetes learning repository that deploys a Tomcat-based Java booking app (login.war) in three progressively better ways: raw Pod/RC/Deployment YAML at the root, a numbered k8s-core/ lab (ConfigMap, Secret, Ingress, storage, RBAC, NetworkPolicy), and a Helm chart deployed to dev and prod through Argo CD. The newer parts are clean and well commented, and helm lint passes for both dev and prod values. The biggest strength is the GitOps setup: one chart, per-environment values, auto-sync for dev and manual sync for prod. The biggest risk is that .env containing a MySQL password was committed on 5 Nov 2026 to a repo that Argo CD pulls from GitHub, and there is no .gitignore rule to stop it.

🧱 Architecture & structure

  • Root (early exercises): mypod.yml → myRC.yml/myapprc.yml (ReplicationController) → mydeploy.yml + mySVCdeploy.yml (Deployment + NodePort 30001, ECR image), with command notes in pod_commands and Rc_comands.
  • k8s-core/ (building blocks, namespace k8s-lab): 00-namespace → 01-config (ConfigMap + Secret injected via envFrom and a /config volume) → 02-ingress (Traefik: /mahaLogin → booking:8080, / → nginx web) → 03-storage (dynamic gp3 PVC or static hostPath PV) → 04-rbac (read-only ServiceAccount) → 05-network-policy (default deny + allow rules). app/Dockerfile builds the image on Tomcat 9 / JRE 17 as non-root UID 1001.
  • helm/myjavaapp/: Deployment + Service templates with _helpers.tpl naming (<release>-myjavaapp); values.yaml defaults, values-dev.yaml (NodePort 30002, Docker Hub image) and values-prod.yaml (3 replicas, private ECR image, LoadBalancer).
  • argocd/: application-dev.yaml (auto-sync, prune, self-heal → namespace dev) and application-prod.yaml (manual sync → production), both pulling main from GitHub.

Flow: git push → Argo CD renders the Helm chart with the env values file → Deployment pulls the image → Service (NodePort / LoadBalancer) exposes port 8080.
